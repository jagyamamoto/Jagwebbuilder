# つまずきと対処

Astro と Cloudflare Pages で、実際に複数のサイトを作って運用するなかで**詰まったところ**の記録です。
うまくいく手順は調べれば出てきますが、**どこで詰まって、何が原因だったか**はなかなか出てきません。

AI に作業を頼むときも、ここに書いてあることは**AI の知識に入っていないことが多い**です。
同じところで止まったら、この文書を読ませてください。

---

## 作るとき

### Astro 7 で、Markdown の拡張が動かない

**起きたこと。** `astro.config.mjs` の `markdown.remarkPlugins` に処理を足したら、書き出しが止まった。

```
`markdown.remarkPlugins` … run on the `unified` processor from `@astrojs/markdown-remark`,
which is no longer installed by default now that Sätteri is the default Markdown processor.
```

**原因。** Astro 7 から、Markdown を処理する部品が **Sätteri** に変わった。
それまでの remark 用の拡張は、別の部品を入れないと動かない。
**AI はこの変更を知らないことが多く、古い書き方で直そうとする。**

**対処。** Sätteri のやり方で書く。しかも Sätteri には Obsidian の `[[ ]]` を読む機能が最初から入っている。

```js
import { satteri } from '@astrojs/markdown-satteri';
markdown: { processor: satteri({ features: { wikilinks: true }, mdastPlugins: [/* 自前の処理 */] }) }
```

`[[会社概要]]` は `url="会社概要"` のリンクとして、`![[写真.png|説明]]` は `url="写真.png"` の画像として
読まれる。あとはその行き先を、サイト上の場所に直すだけでよい（`src/lib/obsidian.mjs`）。

### 「サーバーで動かす設定」にしなくてよかった

**起きたこと。** 公開前のサイトに合言葉（Basic 認証）をかけたくて、Astro をサーバーで動かす設定
（`output: 'server'`）にしようとした。書き出しに時間がかかり、公開の手順も原因の切り分けも一気に難しくなった。

**対処。** **`output: 'static'` のまま、Cloudflare Pages の Functions を足す**だけで足りた。
サーバーで動かす必要があるのは、画面を開くたびに中身が変わるようなサイトだけ。
フォームや認証くらいなら、static ＋ Functions で先に考える。

### ページに言葉を直接書いて、あとから直せなくなった

**起きたこと。** 急いでいて、ページの部品（`.astro`）に文章を直接書いた。
あとで持ち主が「ここを直したい」と言ったとき、どこを直せばよいか本人には分からなかった。

**対処。** **言葉は原稿の側（`content/`）にだけ置き、ページの部品はそれを読むだけ**にする。
軽い修正でも例外にしない。例外を1つ作ると、そこから崩れる。

### `/about` と `/about/` が混ざる

**起きたこと。** リンクによって末尾のスラッシュがあったりなかったりして、片方が転送や 404 になった。

**対処。** `trailingSlash: 'always'` にして、内部リンクは必ず `/about/` の形にする。
`[[ノート名]]` で書けば自動でそうなる。

### 文字が読めない色の組み合わせになった

**起きたこと。** 持ち主が選んだ色が薄く、その上の白い文字が読めなかった。

**対処。** 色の明るさを計算して、上に載せる文字を白にするか黒にするかを**自動で選ぶ**（`src/lib/site.mjs`）。
色は持ち主が自由に決めるものなので、読めない組み合わせを作れないようにしておく。

## 画像

### Obsidian に貼った画像が、サイトに出ない

**原因。** Obsidian の既定では、貼った画像は**保管庫のいちばん上**に入る。サイトが読むのは `content/images/` だけ。

**対処。** `content/.obsidian/app.json` で、貼った画像の入り先を `images` にしてある。
このフォルダを Obsidian で開けば、最初からそうなっている。
ずれたときは `npm run check` が「画像は content/images/ の下に置いてください」と教える。

### 画像を入れ替えたら、関係ないロゴが消えた

**起きたこと。** 記事の画像を差し替えて保存したら、サイトのロゴが出なくなった。

**原因。** 入れ替えた画像とロゴが**たまたま同じ大きさ（バイト数）**で、git が
「ファイル名を変えただけ」と見なして巻き込んだ。

**対処。** 大きさだけで判断しない。記事の画像とサイト共通の画像は**フォルダを分ける**。
差し替えの前後で、参照している側のファイル名も確かめる。

### 拡張子がずれていた

**起きたこと。** 本文は `写真.png` を見にいくのに、実際のファイルは `写真.jpg` だった。手元では気づかなかった。

**対処。** `npm run check` が、本文から参照している画像が実在するかを見る。公開の前に必ず通す。

## 公開するとき

### はじめての公開で `Project not found`

**原因。** Cloudflare Pages は、**置き場所（プロジェクト）を先に作っておかないと**送れない。

**対処。** `npm run deploy` が、無ければ自動で作る（`wrangler pages project create`）。

### `Invalid commit message` で止まる

**原因。** `wrangler pages deploy` の `--commit-message` は**英数字しか受け付けない。**
git の記録に日本語を使っていると、それがそのまま渡って止まる。

**対処。** `npm run deploy` は、英数字の文言を明示して渡している。

### GitHub と連携した自動公開が失敗する

**起きたこと。** GitHub に保存したら自動で公開される設定にしたが、Cloudflare 側の書き出しが失敗し続けた。

**対処。** **連携をやめ、手元から Cloudflare へ直接送る方式に統一した。**
確実で速く、しかも**利用者に GitHub のアカウントが要らなくなる。**
GitHub は、使うとしても履歴の保管だけにする。

### ページが消えていたのに、気づかなかった

**起きたこと。** 公開のあと、あるページが消えていた。確認では「200（正常）」が返っていたので見逃した。

**原因。** **無いページを開いても、404 ではなくトップページが 200 で返ってくる**設定になっていた。

**対処。** **状態コードではなく、本文で確かめる。** `npm run deploy` は、
公開先を開いて**サイト名が本文に入っているか**を見ている。

### 送った直後、古いページと新しいページが混ざって出る

**起きたこと。** 公開した直後に開くと、新しい内容が出たり、古い内容に戻ったりした。

**原因。** 世界中の配信拠点に行き渡るまで、**1分ほど新旧が混ざる。**

**対処。** 待つ。あわてて送り直さない。`npm run deploy` は、落ち着くまで何度か見にいく。

### 2台のパソコンから公開して、互いの作業を消した

**起きたこと。** 1台でブログを、もう1台でページを直していた。片方から公開したら、もう片方の作業が消えた。

**原因。** 直接送る方式は、**差分ではなくサイト全体の置き換え。**
古いままのフォルダから送ると、相手の作業を丸ごと消す。

**対処。** 複数の場所で作業するなら、**公開の前に必ず最新をそろえる**（git で受け取る）。
ひとりで1台なら起きない。

### 大きなファイルを git で送ると `HTTP 400`

**対処。** そのリポジトリだけ、送れる大きさの上限を上げる。

```bash
git config http.postBuffer 524288000
```

## 検索まわり

### 検索避けをかけたページを、ページ一覧に載せてしまった

**起きたこと。** Search Console が「noindex の付いた URL が送信されています」と警告を出した。

**対処。** 準備中（`published: false`）のあいだは、**ページ一覧（sitemap）を空にする。**
検索避けと一覧は、必ずそろえて切り替える（`src/pages/sitemap.xml.js`）。

## あとから機能を足すとき（Functions）

フォームなど、動く仕組みを足したときに踏んだもの。

### 鍵を登録したのに「未設定」と言われる

**原因。** Cloudflare Pages は、**すでに出来上がっている公開物の設定を書き換えない。**

**対処。** `wrangler pages secret put` のあと、**必ずもう一度公開する。**

### 失敗しても、用意したエラー画面が出ない

**起きたこと。** `try { return 処理() } catch { … }` と書いたのに、失敗すると Cloudflare の素のエラー画面が出た。

**原因。** 時間のかかる処理を `return` しただけでは、結果を待たずに `try` を抜けてしまう。

**対処。** **`return await 処理()`** と書く。

### 呼び先の URL がずれる

**起きたこと。** `/shop` のページから `./api/send` を呼んだら、`/shop/api/send` ではなく `/api/send` に飛んだ。

**原因。** 末尾にスラッシュが無い URL では、`./` は1つ上の階層を指す。

**対処。** 呼び先は `/shop/api/send` のように、先頭からの形で書く。

## 文字化けと、見えない文字

### Windows のメモ帳で保存したノートの設定が効かない

**原因。** メモ帳は、ファイルの先頭に**目に見えない印（BOM）**を付けることがある。
先頭の `---` が先頭でなくなり、設定として読まれない。

**対処。** 読むときに外している（`src/lib/obsidian.mjs`）。Obsidian で書けば付かない。
